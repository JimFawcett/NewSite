Chapter 2. - Rust Data

Types, type deduction, ownership

2.0  Prologue

Compiler-enforced memory safety is a primary Rust feature, implemented through a strict ownership policy that prevents concurrent aliasing and mutation for any instance of a Rust type.
Definition: Alias Two or more identifiers are bound to part or all of the same memory location.
Example: let mut iden1 = vec![1,2,3]; let iden2 = &iden1[1]; Definition: Mutation Operations on an identifier change its bound value.
Example: iden1.push(4);
Value refers to the state of an identifier's bound instance. For a String, that is the collection of all its characters. Changes to String state may change its memory allocation when the original allocation lacks capacity - leaving all aliases of the changed identifier holding invalid references. When new names bind to an existing value, blittable types copy that value and non-blittable types move it. A move transfers ownership, so the original owner can no longer access that value. References support borrowing - providing access to the owning instance's value while suspending the owner's ability to mutate. When borrowing ends, the owner regains the ability to mutate.
References are borrows
/* attempt to mutate after borrow */

let mut s = String::from("s is owner");
slog(&s);

{
  let rs = &s;  // borrow s
  // statement below fails to compile
  // owner can't mutate after borrow
  // s += " with stuff";
  slog(&rs);
}  // borrow ends here

s += " with stuff";
slog(&s);
Data may have any number of immutable references - often called shared references. Only one mutable reference can be taken to data that has no other references; that is called a unique reference. References are often called borrows, because the reference borrows the ability to view or mutate the referend. When an immutable reference is taken on an instance, that instance cannot be mutated until the borrow ends, as shown in the code block to the left. When a mutable reference is taken, only that reference can mutate the instance until the borrow ends, usually at the end of the scope in which the reference is defined. The Rust compiler enforces all of these rules. When a rule is violated, the compiler emits a useful error message that helps a designer fix the violation.

2.1  Data and its Life Cycle

Rust data comes in two flavors (see basic-types for details):
  1. Blittable types:
    Stored entirely in one contiguous block of stack memory.
    • Basic Types:
      u8, i8, u16, i16, u32, i32, u64, i64, usize, isize, f32, f64, bool, char, str
    • Aggregate Types:
      array, tuple, struct if all their items are blittable
    • User-Defined Types that have all blittable members and are marked Copy with #[derive(Copy)]
  2. Non-Blittable types:
    Control block stored in one contiguous block of stack memory with references to data held in the heap.
    • Std Library Types:
      String, Box, Vec, VecDeque, LinkedList, HashMap, HashSet, BTreeMap, BTreeSet, BinaryHeap
    • Aggregate Types:
      array, tuple, struct if each has at least one non-blittable member
    • User-defined types that have at least one non-blittable member
Figure 1. String Move
Blittable data values are copied:
let x = 3.5; Creates an x:f64 on the stack initialized with the value 3.5.
let y = x; Creates an y:f64 on the stack and copies x's value into y. x is still valid.
Non-Blittable data values are moved:
let s = String::from("a string"); Creates an s:String control block on the stack pointing to continguous heap memory containing the characters "a string"
let t = s; Copies the s:String control block to t (still pointing to s's characters) and marks s as moved.
When x and y go out of scope - when the thread of execution leaves the scope in which they are defined - the stack frame is marked as free and may be overwritten by any subsequent stack allocation. When s and t go out of scope, Rust calls the String Drop trait method on t, deallocating its character memory in the heap. Drop is not called on s because s no longer owns anything on the heap. Figure 2. String Clone
An alternative exists. Many standard library types, including String, implement the Clone trait, giving them a clone method. A designer can replace an invalidating move with a clone, like this:
let s = String::from("a string"); Creates an s:String control block on the stack pointing to continguous heap memory containing the characters "a string"
let t = s.clone(); Creates a t:String control block on the stack pointing to continguous heap memory containing a copy of the characters "a string"
Now s and t are both valid, each pointing to separate character allocations on the heap with identical contents immediately after cloning. When s and t go out of scope, Rust calls drop() on both because each owns a unique character array allocation. User-defined types can implement clone by deriving the Clone trait with #[derive(Clone)] above the type definition.

Aggregate types are blittable only when all members are blittable - no Strings, Vecs, etc. In that case they can acquire the Copy trait by declaring derived Copy: #[derive(Debug, Copy, Clone)] struct my_struct { ... } For this declaration, the compiler generates these traits.
  • Debug enables the {:?} format specifier, which uses a standard formatting process for each Rust type.
  • Copy causes the compiler to copy an instance's value by blitting (memcpy) to the new location. The compiler refuses to derive Copy if any member is non-blittable or the type already implements Drop.
  • Clone is not called implicitly. A designer can call clone() explicitly, paying whatever performance penalty the copy requires. Implementing Copy also requires implementing Clone.
Attempting to derive Copy on a non-blittable aggregate type is a compile error. However, you can implement Clone using the clone method on any non-blittable member that has the Clone trait.

2.2.3  Slices of Aggregate Types:

A slice is a non-owning view into an aggregate data structure, covering part or all of it. Consider an array: let arr = [1, 2, 3, 4, 5, 6];
  • let slc1 = &arr[..]; // view the entire array
  • let slc2 = &arr[0..6]; // same as slc1
  • let slc3 = &arr[..3]; // views elements [1, 2, 3]
  • let slc4 = &arr[1..]; // views elements [2, 3, 4, 5, 6]
  • let slc5 = &arr[1..4]; // views elements [2, 3, 4]
Slices apply to array-like types - arrays, vectors, and strings. String slices are only reliable when all characters are ASCII; we discuss this further in the next section.

2.2.4  String Types:

Rust provides two native string types: String and str, and two types for C language bindings: OsString and CString. This section focuses on String and str. The str type is part of core Rust; String is provided by the std library. Both hold sequences of utf-8 characters, which range from 1 to 4 bytes in size. String is implemented using Vec<u8>, so indexing yields a byte - a whole character only for ASCII, and only part of a character for multi-byte encodings. You cannot directly index Strings.

2.2.4.1  String

To retrieve the ith utf-8 char from String s, use: s.chars().nth(i).unwrap(). chars() is an iterator that finds utf-8 character boundaries. nth(i) calls next i times and returns a std::option containing Some(ch) or None. Successful indexing returns Some(ch), which can be used directly. This is an O(N) process because it walks the string to find character boundaries. unwrap() extracts the character directly, panicking on failure. When a panic is not appropriate, use matching to handle the option. Option processing is discussed in the next chapter, Operations. This method works for all utf-8 character sets. For languages that use diacritics, though, diacritics encode as separate chars even though native speakers consider them part of an adjacent character (Hindi, for example). The chars() iterator does not handle that case. Here's a reference: ch08-02-strings in the Rust Book Strings are not blittable. Rebinding a string transfers ownership, and taking a borrow reference suspends the owner's ability to mutate until the borrow ends.

2.2.4.2  str

The str type represents literal strings like "a literal string". Str instances are contiguous blocks of memory, often on the stack, and so are blittable. You almost always encounter them as references, &s. Str instances convert to String in several ways. Two options:
  1. let s = String::from("a literal string");
  2. let s = "a literal string".to_string();
You can create a str by taking a slice of a String or a literal string:
  1. let s1 = "Hello world"; // slice of the whole literal
  2. let s2 = &s[1..3]; // second through 4th bytes of s
Both s1 and s2 have type &str, a reference to a literal string. Taking a complete slice always works. Partial slices like s2 may not correctly represent characters because Rust chars are utf-8 with sizes ranging from 1 byte (ASCII) to 4 bytes (math symbols and emojis). amos provides an excellent discussion of utf-8 strings.

2.2.5  String Examples:

The String type has methods:
  • let s = String::new();
    Creates new empty String instance
  • let s = String::from("a literal");
    Creates instance from literal
  • let t = s.replace("abc","xyz");
    t is a copy of s with every instance of "abc" replaced with "xyz"
  • s.len();
    returns length of s in bytes, not chars
  • let slice = s.as_str();
    returns slice of entire String s contents
  • s.push('a');
    append char 'a' to end of s.
  • s.push_str("abc");
    appends "abc" to the end of s
  • let st = s.trim();
    returns string with leading and trailing whitespace removed.
  • let iter = s.split_whitespace();
    returns iterator over whitespace separated tokens
  • let iter = s.split('\n');
    returns iterator over lines
  • let iter = s.chars();
    returns an iterator over the utf-8 chars of s

/*-----------------------------------------------------------
   Note:
   Strings hold utf8 characters, which vary in size, so you
   you can't directly index String instances.
*/
#[allow(dead_code)]
pub fn at(s:&String, i:usize) -> char {
  s.chars().nth(i).unwrap()
}
/*-----------------------------------------------------------
   note:
   - order n, as str chars are utf8, e.g., from 1 to 5 bytes
   - this ugliness is one way to index
   - see below for another, not much better way
*/
#[allow(dead_code)]
pub fn vectorize(s: &str) -> Vec<char> {
  s.chars().collect::<Vec<char>>()
}
/*-- note: order n, from vectorize -- prefer at, above --*/
#[allow(dead_code)]
pub fn get_char(s:&str, i:usize) -> char {
    vectorize(s)[i]
}
/*-- stringize - order n --*/
#[allow(dead_code)]
pub fn stringize(v: &Vec<char>) -> String {
  return v.into_iter().collect()
}
The functions shown above main in demo code help format program output into a readable form.
Rust Strings holding utf-8 characters is both good and bad. On the good side, they represent virtually anything a console can emit - ASCII chars, math symbols, Arabic fonts, European diacritics, and emojis. On the bad side, you can't index a Rust String in constant time, and converting to other data structures can get messy.

2.3  Structs

In Rust, most structs are aggregates of one or more fields where fields may be arbitrary types, named types, or unit type:

  name:String, occupation:String, age:u32,

    struct Person (
  String, String, u32,

  3. StructExprUnit: 
    struct Person;

2.4  Enumerations

An enumeration is a type identifier with a set of enumeration item fields, which may be:
  • ItemDiscriminant: a named integral value enum Names { John, Sally = 35, Roger };
  • ItemTuple: a named tuple with items specified by type enum Names { Alok(String, f64), Priya(String, f64), Ram(String, f64) };
  • ItemStruct: a named struct with items specified by name and type enum Names { Jun { occupation: String, age: f64 }, Xing { occupation: String, age: f64 }, Shi { occupation: String, age: f64 }, }
Enumerations can be generic. A common example is Option: enum Option<T>{ Some(T), None } which serves as the return value of functions that may or may not produce a result. Here are some examples:

2.5  Type Aliases

Type aliases provide an alternate name for an existing type while remaining the same type. Construct an alias like this:
  • type PointF = (f64, f64, f64); // tuple of three doubles
  • type VecPoint = Vec<PointF>
Aliases provide meaningful application domain names for standard types and shortcuts for long type names. Note that Rust uses snake_case for functions and CamelCase for types.

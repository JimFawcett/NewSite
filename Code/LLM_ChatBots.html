Spec-Driven Design: Chat Bots

what happens between a question and the reply, and what a browser chat bot cannot do

Synopsis:
This page describes the browser and mobile chat bot, the most familiar way to reach a language model, and the limits its security model imposes.
  • A chat application sends each question to the provider's datacenter as an API request and displays the API response.
  • A browser or mobile application cannot edit local files.
  • Chat bots suit question and answer conversations, not multi-file work.

1.  Chat Bot Architecture

The user types a question into a chat application such as ChatGPT. The application sends the question to the provider's datacenter as an API request. An API server there passes the request to the model for processing, and the reply returns to the application as an API response. The model keeps nothing between those requests. The application resends the whole conversation each time, per Context Section 2. ChatGPT generated Fig 1 from the prompt “create concept diagram for LLM AI Chatbots”. 2.  Takeaways

  1. Web and mobile applications work within limits their security needs impose:
    1. They cannot edit local data. A chat bot copies a file, modifies the copy, and sends the result to the local download folder.
    2. To act on several files, the user packs them into a zip file and pastes it at the end of the prompt.
  2. Chat bots work well for question and answer conversations.
  3. They are awkward for multipage presentations and other multi-file work. The LLM CLI page describes the tool that removes that limit.

# Lessons Learned — Spec_driven_TextFinder

Started 2026-09-25 08:54 CDT.

1. Starting with Spec and Structure files lets you focus on what the code does and its top level parts. That is quick and avoids inappropriate default decisions while writing code.

2. Factoring the Spec into a project functional spec and an implementation spec for each part lets you separate what you want this code to do from low level error handling and I/O details that depend on language and platform.

    a) This was imperfectly implemented in this project. I plan to make small revisions at a later time.

3. The Constitution file requires all code to be generated from the spec. Specs get changes and additions, then all code is generated from the specs. Claude does that accurately with a simple prompt to generate code.

4. I used Prompts_*.md to capture sequences of interactions with Claude Code. That helped me get started again after several days away and is intended to help readers understand this process.

5. Documentation is handled with README.md files and separate web pages.

    a) README files are almost always effective and need little modification.

    b) Webpage documentation was generated by Claude using prompt files and individual prompts.

      - I used Text_Tone.md to set the voice for generated text and provided a PageExample.html to define the page structure, styles, and javascript behaviors
      - Getting readable useful documentation took a lot of experimentation.
      - This documentation process is still evolving

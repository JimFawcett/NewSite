Spec-Driven Design: LLM CLI

working with an LLM from a terminal, with access to local files and tools

Synopsis:
This page describes the LLM command line interface, the tool the Spec-Driven project was built with.
  • A CLI program on the user's machine talks to the LLM on one side and to local files and tools on the other.
  • Unlike a browser or mobile app, the CLI reads, edits, and deletes local files.
  • The output is only as good as the structure and ideas the user supplies.

1.  CLI Architecture

The CLI gives the user another way to reach an LLM, without the security limits of a browser or mobile app. The user downloads it from the provider: OpenAI for ChatGPT, Anthropic for Claude. In Fig 1, the user at a terminal exchanges requests and replies with the CLI program. That program talks to the LLM on one side and to external files and tools - documents, databases, the web, and local utilities - on the other. The model still keeps nothing between requests. The CLI resends the conversation on every call, and that conversation now includes the full text of every file the CLI read on the user's behalf. 2.  Takeaways

  1. The user's terminal replaces the browser or mobile app of the Chat Bots page.
  2. The LLM CLI application handles interactions with the LLM in place of the browser application.
  3. Unlike a browser or mobile app, the CLI can read, edit, or delete files on the local computer.
  4. Authors have used CLIs to create presentations and to write books or assist in writing them. That work obeys the law “garbage in = garbage out”, and the garbage that comes out is known as AI Slop.
  5. AI assistance works well when the user treats it as an assistant: the user supplies most of the content structure and ideas, and edits the output carefully.
  6. The Claude Code CLI assisted throughout the Spec-Driven project these pages document.
